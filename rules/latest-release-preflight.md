## Check current DanceFlow releases before each workflow

Before every new workflow run, people and agents must check the latest stable official releases and observe the actual installed/imported runtimes. Read `Workflows/DanceFlow/workflows/release-preflight.md`, `DanceFlow/ecosystem.md`, `Workflows/scheduled-danceflow-tool-use.md`, the complete `Workflows/DanceFlow/capabilities/index.md` and applicable Potential problems. Use the installed `Tools/DanceFlow.ps1 -Releases --output NEW-RUN/releases.json` checker, or the supported official release/API route if the checker is unavailable; retain a fresh receipt and resolve unavailable queries before claiming currency. A current checkout or old report is not a new check.

Review the whole ecosystem and use every applicable supported feature that serves the task. The full FrameRudiments compositor, authoring, 222-view registry and profiling routes are documented in `Workflows/DanceFlow/workflows/framerudiments-complete.md`; select actual source-clock, caption, native motion, stem driver, matte/keyframe, sprite/3D, emitter, feedback-routing, quality and analysis features rather than defaulting to a familiar basic renderer. Compose canonical tools and improve a demonstrated reusable gap in its owner, or record why the existing tool meets the need. Keep independent identities, model-local storage, privacy/costs, source clocks, schedules and separate public-site/plugin action-time gates intact. Guidance availability is not proof another running chat adopted it or that a feature ran.
