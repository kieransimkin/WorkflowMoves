## WordPress metadata is the only EPK timing-file authority

- Standing instruction from Kieran, 11 October 2026: every EPK player, lyric renderer, cue consumer and timing-file download must reference the timing attachments selected in that page's WordPress EPK Timing metadata. Never hardcode lyric or cue timing URLs in an EPK's content, scripts, data attributes, template, generated payload or fallback. Concrete URLs belong only in the canonical metadata and its plugin-generated runtime configuration.
- Use the supported metadata-derived runtime contract (`danceMovesConfig.lyricTimingUrl` and `danceMovesConfig.cueTimingUrl` in the current WordPress integration). Keep exact URLs, query parameters and percent encoding intact. Resolve the configuration before starting a consumer; changing the selected attachment must update every dependent consumer after reload without a body edit. Do not create an independent page-local timing-source override.
- Bind timing-download controls to the same metadata-derived source. When a required source is unavailable, retain the audio and readable lyrics, expose an accurate unavailable state and disable the corresponding download; never guess, silently fall back to an old hardcoded URL or clear working metadata automatically.
- Multi-track or alternate-version pages must preserve the supported exact track/master association; a page-level field is not authority to apply one arbitrary timing file to distinct tracks. Preserve approved clean-version transformations and cue choreography. Missing mappings or approval remain explicit holds.
- On every EPK publication and weekly run, scan fresh saved content and rendered HTML for hardcoded timing-file literals, compare all consumers/downloads with persisted selected attachments, verify hosted bytes/parser state, and prove a metadata-only source change reaches the consumers. Audit both past and future releases. Passing pages must not be republished.
- Repair through a fresh-source narrow merge, keeping the canonical live design, controls, audio, lyrics, links and accessibility. Migrating an existing working cue source into metadata must identify the exact existing attachment, preserve byte identity and state whether it is artist-approved canonical or merely the preserved working source. It must not silently approve or retime that source. Obtain the existing exact-payload action-time confirmation before public saves. Record staged, published and verified states separately; reconcile durable mirrors/generator inputs so later builds cannot reintroduce a literal.
