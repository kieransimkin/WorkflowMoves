## Use and improve maintained DanceFlow tools

Standing instruction from Kieran, 16 October 2026: every chat, agent, project and recurring workflow should actively use and improve the maintained tools as much as is useful for its authorised task. Read current shared instructions at task start and at material tool handoffs, including during an existing chat. For My Songs work, consult `Z:\My Songs\DanceFlow\ecosystem.md`, `Z:\My Songs\Workflows\scheduled-danceflow-tool-use.md` and the applicable skills and Potential problems guidance.

- Route offline Shorts, Canvas-style clips and lyric visualisers through **FrameRudiments** (`Z:\My Songs\Tools\FrameRudiments.ps1`, `Workflows/framerudiments-rendering.md`); use **StemLab** for saved or necessary new audio/timing/loop evidence, **DanceRudiments** for native movement and bounded recording playback, and **DanceMoves** for live web clocks, effects, input and playback. Review the other ecosystem tools' complete relevant capabilities and compose their supported file/API contracts when useful. Preserve independent project identities, including Short Shifter.
- Inspect actual released, installed and imported identities before relying on a capability. Prefer existing shared primitives to another private renderer, analysis engine, motion engine or copied helper. Keep release-specific artwork and scene decisions in adapters. A loaded library, installed package or written instruction does not prove integration.
- For substantial tool use, identify a concrete reusable improvement in capability, composition, reliability, performance, ergonomics, evidence or documentation. Implement the smallest worthwhile in-scope improvement in its canonical repository, with appropriate verification, maintained skills/workflows and matching publication. If the tool already meets the need, record that conclusion; do not invent changes, expensive model runs, scans, generation or extra work to satisfy a quota.
- For authorised maintained-tool software releases, publish tested GitHub releases and configured package registries immediately through their established automated checks. Kieran's direction removes a separate human confirmation or environment-reviewer gate for these software publications. Preserve mandatory CI, immutable versions/assets, source/version ownership, registry verification and real access/credential requirements. Social publication schedules, WordPress deployment/public-save gates, rights, privacy and cost limits retain their own requirements.
- Share actionable findings privately through supported agent channels or the owning chat's `.codex/coordination/` record. Do not wake unrelated chats or insert routine coordination into their conversations. Shared configuration makes the guidance available; claim adoption by another running chat only with evidence of receipt and use.
