# WordPress blog API transport

The 19 October API-first browser workaround prefers the documented [Posts](https://developer.wordpress.org/rest-api/reference/posts/) and [Media](https://developer.wordpress.org/rest-api/reference/media/) REST endpoints for blog inventory, attachments, drafts and authorised publication. It preserves the distinct EPK helper and does not deploy plugins or change credentials. Use the existing encrypted Application Password contract in `wordpress-epk-rest-api.md`. Never print credentials or request headers.

Use PowerShell 7.5 or later with `tools/wordpress_blog_api.ps1` (installed as `Tools/WordPress Blog API/wordpress_blog_api.ps1`). Inventory and ReadPost are non-mutating. Every mutation requires an exact UTF-8 manifest SHA-256, `-Execute` and a new receipt path. UploadMedia checks the local file hash, MIME, explicit public-use basis, exact attachment metadata and independently downloaded original bytes. CreateDraft checks current all-status slugs, exact body bytes and retained fields; category/tag membership is exact even when WordPress returns a different order. The manifest parser preserves date strings and their explicit offsets. PublishPost requires explicit immediate-publication authority, completed prepublication checks and an unchanged reviewed snapshot; it changes only draft status. A failed/uncertain request or existing receipt requires readback, never a blind repeat.

SchedulePost is the default committing route under Kieran's future-publication rule. It requires explicit scheduling authority, completed prepublication checks, an unchanged reviewed draft, an offset-bearing local publication time and its named timezone. It checks the offset against the named zone, derives and compares the exact UTC time, and rejects a time less than five minutes ahead. Its single mutation sends only `status=future` and `date_gmt`; readback must retain all reviewed fields and the exact UTC schedule. Re-read each local date, time and timezone immediately before committing. London changes from BST to GMT on 25 October 2026; a batch crossing that date cannot use one fixed offset.

Before scheduling, check the exact body, title, featured artwork and hosted media in the current theme at desktop, tablet and mobile widths. A locally substituted response is candidate evidence, not a public article. A saved schedule is not publication: retain a due-date verification queue, and after actual publication independently fetch the fresh anonymous page, inspect every media item and verify video progression with user controls. Record actual listening, synthetic behaviour and technical playback separately. Preserve all rights, privacy, fresh-artwork, duplicate and voice checks. Use PublishPost only when Kieran specifically requests immediate publication for that exact article or batch.

Manifest fields: UploadMedia uses `file`, `sha256`, `slug`, `mime_type`, `title`, `alt_text`, `caption`, `public_use_basis`. CreateDraft uses `slug`, `title`, `content_file`, `content_sha256`, `excerpt`, `categories`, `tags`, `featured_media`, `evidence_reviewed`. SchedulePost uses `post_id`, `expected_review_sha256`, `scheduling_authorized`, `prepublication_verified`, `publication_time`, `timezone`, `date_gmt`. PublishPost uses `post_id`, `expected_review_sha256`, `immediate_publication_authorized`, `prepublication_verified`. Authority/check fields must be actual JSON booleans. No mode edits an existing published article.

## Potential problems

- An uncertain API outcome or existing receipt requires a fresh identity read; never repeat the mutation blindly. Keep the initial receipt even when later verification fails.
- A changed draft snapshot stops the commit. Review the fresh copy and issue a new manifest rather than carrying an old approval into different content.
- Missing browser video-recorder binaries are a runtime hold, not evidence of capture. Match Python and its native dependencies, provision only the needed official Playwright recorder tools into the project-owned runtime, retain failed attempts, and verify actual encoded progression and owned-process exit. Never use the disabled in-app browser as a fallback.
