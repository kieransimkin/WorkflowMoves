# Campaign media EPK reconciliation

Apply the project rule during publishing, campaign/platform monitoring, reply audits and weekly release sync.

1. Reconcile current catalogue, release records, publishing receipts/queues and original public items. Record exact song/campaign and page IDs. Related press/alternate pages receive only material appropriate to their actual version.
2. Build one ledger row per distinct creative asset. Record exact render hash or explicit verified cross-post mapping, all platform IDs, format and publication date. Prefer the verified public YouTube publication of a cross-posted video. Preserve different edits and versions. Never infer same asset from titles.
3. Verify public availability and public-safe reuse separately from scheduling, receipts, playback and permission to embed. YouTube oEmbed identifies an item and offered embed but does not prove playback. Record unavailable sources/uncertain associations as holds. Artist social promotion belongs under campaign media, separately attributed from independent coverage.
4. Inspect anonymous current output and fresh saved editor content. Count visible links/players; ignore metadata, hidden markup and script strings. A video reference in metadata or a watch link alone is not an embed. The offline Tools/EPK Campaign Media/audit_campaign_media.py checker reports identity/coverage candidates; actual rendered visibility and playback need separate checks.
5. Stage a narrow cumulative merge. Preserve hero, artwork, controls, timing attachments/configuration, lyrics/cues, motion, downloads, publicity and design. Use a titled standard https://www.youtube.com/embed/VIDEO_ID player or supported privacy-enhanced host. Match aspect ratio, lazy load below fold, retain fullscreen/direct watch links and avoid autoplay. Respect minimum player dimensions and consent. Shorts use the same embed ID contract in a portrait container. When YouTube embedding is unavailable, resolve the exact original approved render and poster from release-local publication evidence. Search WordPress for an existing exact asset before upload, compare hashes and reuse matching bytes. Otherwise upload the original file to WordPress through the supported uploader, verify attachment identity and anonymous hosted bytes, and use a responsive controls/playsinline/preload-metadata HTML video without autoplay. Keep exact source, required disclosures and rights/access gates. Never download a file by bypassing YouTube restrictions. If original bytes or hosting cannot be verified, retain a factual link and explicit hold; never remove a YouTube age restriction.
6. Validate complete candidate hashes, UTF-8, timing literals and retained features. Inspect desktop/tablet/mobile layout, controls, keyboard access and actual progression. Apply Workflows/epk-mobile-motion.md and existing evidence gates without adding motion to static media cards. Label synthetic/local rendering and physical device limits.
7. Use the existing exact candidate public-save confirmation unless this exact addition independently meets limited standing publicity permission. Re-read editor immediately before save; re-merge and revalidate if changed. Save once, reopen and match exact payload/unchanged metadata, then verify anonymous source and responsive retained features. A save notice alone is not completion.
8. Update release-local ledger, mirrors and generator inputs. Preserve history. Keep recorded, staged, awaiting approval, published and verified-live states distinct. Do not resave passing pages. Scheduled publication creates a pending reconciliation action, never a live claim.

## Checker contract

Input ledger JSON rows contain epk_id, url, kind (video/short/post), publication_state (verified_public only after original-source review), optional asset_group, embed_blocked_reason, wordpress_url and source_hash_verified. Public-use eligibility, visible rendering and actual playback are separate evidence. Grouping requires an explicit asset identity; prefer YouTube once per group. Compare content.rendered in a WordPress catalogue by exact platform item identity.

## Artwork-first hero playback

Keep the hero at the approved square artwork geometry. The video stays behind the 1:1 artwork until an accessible Play button is pressed. Do not stack a second full video above the cover. Use `Tools/EPK Campaign Media/compose_epk_cover.py` and its paired `epk_cover_player.js` for a fresh-source additive conversion of the campaign featured player. Its iframe is an inert template until the visitor gesture, then requests playback with native YouTube controls. Return to artwork removes the iframe and restores the cover; pagehide resets the same state. Preserve all other media, CSS/scripts, lyrics, timing selections and existing mobile input owners.

The offline audit distinguishes declared deferred embeds from active embed source. Neither proves playback. On every video audit, click all applicable controls and record an advancing media timeline, ready/paused state, asset identity and any buffering, age, regional, embedding or browser-control failure. Check square cover geometry and revealed bounds on desktop/tablet/mobile, keyboard activation, close/reopen, teardown and retained source links. Recheck source before an authorised public save, then verify persisted public content and real controls; retain exact candidate/saved hashes and limitations.
