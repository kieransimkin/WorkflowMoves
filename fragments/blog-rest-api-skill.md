## API-first blog transport

Under the 19 October API-first stability workaround, use the documented WordPress Posts/Media REST API for semantic blog reads, uploads, drafts and authorised saves, rather than older browser-only transport guidance below. Follow `Workflows/wordpress-blog-rest-api.md` and the maintained `Tools/WordPress Blog API/wordpress_blog_api.ps1` helper. SchedulePost preserves the reviewed draft and checks an offset-bearing local time against its named timezone and UTC schedule; PublishPost requires explicit immediate-publication authority. Preserve encrypted credentials, exact manifest and fresh-source gates, all article/media/voice checks, timing authority and independent anonymous visual verification after actual publication. Browser UI is required only for an actual remaining UI operation through an allowed surface; the in-app browser remains disabled. A persisted future schedule does not prove publication, display or playback.
