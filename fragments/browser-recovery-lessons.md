## Known signatures and bounded recovery

Read this section before repeating recovery attempts. These are dated observations, not universal diagnoses. Consult the private project record `Reports/browser-control-lessons-2026-10-13.md` for the exact evidence and remaining limits; never copy account data, credentials or private integration identifiers into issue reports or reusable packages.

- **Kernel asset creation fails before execution:** `failed to write kernel assets: The system cannot find the path specified. (os error 3)` is not evidence of platform sign-out, missing saved schedules or a tab-specific failure. A visible browser or another chat's successful read does not prove that this chat's execution helper works. Check advertised runtime/module paths and ordinary temporary roots read-only; a valid root does not prove the failing subdirectory exists. Retain the exact error, tool availability and evidence date.
- **Reset versus reconnect:** a supported kernel reset can succeed while the next harmless execution still fails. After one reset and one distinct documented reconnect test reproduce the same pre-execution fault, checkpoint and seek a genuinely different supported connection recovery. Do not repeat the same reset/bootstrap loop or open unlimited tabs.
- **Temporary-root experiment, 13 October:** a reversible TEMP/TMP-only test parsed correctly but did not restore the already-running failing connection. It was rolled back exactly. Empty directories did not establish adoption or successful kernel creation. Do not present temporary relocation as a proven fix, leave an unverified configuration change active or infer the precise missing path.
- **Stopping a helper is not a browser restart:** an explicitly authorised, precisely owned helper stop left its client at `Transport closed` without a verified replacement. Do not repeat this as a generic remedy, stop other helpers or escalate to stopping Codex. A reset cannot create a new app-managed transport. Use a supported manager reconnect/reload if actually exposed, or the separately approved fresh-chat route below. Official app-server documentation of `config/mcpServer/reload` is not proof that this conversation can call it; do not invent a private endpoint or manipulate the app's live transport.
- **Tab cleanup versus restoration:** the supported working connection closed nine completed read-only tabs and verified a new authenticated Studio tab on 13 October, while the failing conversation's harmless call still returned `Transport closed`. Closure of the old inaccessible tabs remained unverified. This supports ownership-aware cleanup, not the claim that tab count caused or repaired the missing-path error. Preserve unsaved forms and other owners' work.
- **Credit correlation is unproved:** current ordinary usage was allowed during the failure. A user's observed recurrence near exhausted credits is useful symptom history, not established causality. Do not buy credits, redeem a reset, alter account settings or claim a billing fix without separate authority and verification.

Before asking Kieran to act, use the supported panel opener for the exact page and check its result. `queued` is not opened. Do not automate Codex settings through Computer Use, inspect cookies/profiles/session stores, change trust or approval settings, or substitute an unsupported browser driver. Preserve the existing task's verified actions and inspect independent queues before any retry so a connection failure cannot cause duplicate submissions.

Record separately: configuration validated, helper state changed, tabs independently closed, browser execution succeeded, authenticated access verified, intended panel opened and the original task completed. Only successful execution of the previously failing operation establishes that part of recovery. Shared instructions prevent repeat mistakes; they do not guarantee that the app will never fail again.
